ORCHESTRA SYSTEM MAPPING

The Maestro’s
Score

We chose the name AI Agent Orchestra because real-world software requires harmony, timing, constraints, and deliberate human direction.

ORCHESTRA TECHNICAL SYSTEM MEANING
Conductor The developer directing the agent and setting rules
Score The instructions, system prompts, schemas, constraints
Musicians The AI models, reasoning engines, and available tools
Instruments Functions (classifying inputs, checking records, mutating state)
Performance The working application responding to real scenarios
Rehearsal Testing, debugging, handling ambiguous and unexpected inputs
"An orchestra does not generate noise; it plays a score under deliberate human direction. Your AI should do the same."

BEYOND TEXT GENERATION

What is an
AI Agent?

An AI model, a chatbot, an agent, and an automation workflow are not interchangeable terms.

A Chatbot

Primarily responds to messages with conversational text. It cannot query databases, call APIs, or mutate application state.

An Agent

Interprets input, evaluates constraints, selects permitted tools, and alters application state with verifiable results.

"AI is useful when its output changes what the system can do — safely, visibly, and verifiably."

The event becomes worthy of the name when participants demonstrate more than prompt answers: the system reads an input, decides what action is appropriate, executes an approved operation, and renders the result.

THE THREE-DAY ARC

The Three-Day
Journey

The three days are meant to be a deliberate progression, introducing one capability layer at a time:

DAY 01: CREATE · THEME: BUILD THE STAGE

Website Recreation Challenge

Recreate a polished interface using AI coding tools (~3 hours proposed).

DAY 02: CONNECT · THEME: INTRODUCE THE MUSICIANS

Minimum Working Agent Workflow

Understand message classification, tool functions, and API protection (~2 hours proposed).

DAY 03: CONDUCT · THEME: CONDUCT THE ORCHESTRA

Live Challenge, Edge Cases & Demonstration

Build, test, adapt to a surprise scenario, and present live to judges (Full day).

"Participants are not expected to learn web development, model APIs, agent design, and backend hosting simultaneously."

DAY 01 · DISCOVER & DESIGN SPREAD 03 // LEFT
DAY 01 · ~3 HOURS PROPOSED

From Reference
to Reality

Participants receive a target developer portfolio or reference website and use an AI coding tool to recreate the experience as closely as possible.

01
Visual Deconstruction: Inspect the reference website and identify its main sections, layout, typography, and visual hierarchy.
02
Iterative Prompting: Use Antigravity or approved tools to generate components, iterating on the result rather than accepting the first output.
03
Local Verification: Confirm that the website runs smoothly on localhost, with working navigation, clean layout, and responsive styling.
★
Midpoint Power-Up: A surprise feature requirement added halfway through without breaking existing code!
"Day 1 tests how well participants direct and refine an AI coding tool, rather than who can write the longest prompt."

DAY 02 · ~2 HOURS PROPOSED

Teach the
Interface to Act

Day 2 is the technical bridge. Participants understand what an agent does, inspect a working example, and modify a simple workflow that classifies messages and returns structured results.

THE MINIMUM WORKING AGENT PATTERN

1. Input message received from user chat
2. AI model interprets & outputs structured JSON
3. Application validates schema & safety guardrails
4. Approved tool mutates simulated application state
5. Website visibly reflects the updated result

Memory, multi-agent networks, databases, webhooks, and production cloud deployment are demonstrations or optional extensions — not prerequisites.

DAY 03 · BUILD, ADAPT & PERFORM SPREAD 05 // LEFT
FULL DAY MAIN EVENT

Build Something
That Responds

Teams implement their agent workflow inside their local application, stress-test it against edge cases, survive a live surprise scenario, and demonstrate live to judges.

THE 14:15 SURPRISE SCENARIO

The surprise tests whether teams built a robust baseline rather than repeating a rehearsed script. E.g., an unexpected input that omits a required field, conflicting data, or an unknown identifier requiring human escalation.

"A live working demonstration beats twenty slides. Judges will test your system with live, unfamiliar inputs directly on your laptop."
